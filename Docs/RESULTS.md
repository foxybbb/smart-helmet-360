# Направления 1–5: результаты тестов (UE5 с эталоном + реальный шлем)

Скрипты: `Tools/experiments/directions.py` (все варианты), `ue_dataset.py` (генерация в UE), `ue_eval.py`, `real_eval.py`.
Сырые цифры: `Docs/results/*.json`. Иллюстрации: `Docs/media/`.

## Стенд в Unreal Engine (неточности по каждой камере, seed 1)
- погрешность установки σ = 3° (выпало до 10°);
- разброс дисторсии k1 σ = 0.03 (от −0.085 до +0.056), k2..k4 пропорционально;
- экспозиция σ = 0.8 ступени (множитель 0.56…1.55), баланс белого σ = 0.08;
- виньетирование cos⁴ (сила 0.5), шум σ = 2;
- рассинхрон триггера до 0.5 с, оператор идёт по кругу и поворачивает со скоростью 25°/с (только датасет B);
- эталон — идеальный куб 360° из центра каски в момент триггера.

- Невязка совмещения: 4.2 px (общий объектив) → 0.98 px (объектив на каждую камеру).
- Кривая объектива «угол → пиксель» у края кадра: 37–138 px (общий объектив) → 19–43 px (на каждую камеру). Абсолютные f и k1 по одной сцене не разделяются, поэтому для точной кривой у края нужна разовая калибровка каждой камеры по ChArUco.
- **Рассинхрон ломает самокалибровку:** на датасете B ошибка у части камер вырастает до 7–10°. Калибровать нужно по кадрам, где оператор неподвижен, или синхронизировать камеры аппаратно.

## Выводы
1. **Самокалибровка обязательна:** +2.1 дБ к номиналу, повороты точнее 1°. Но калибровать нужно по неподвижным кадрам: рассинхрон её портит.
2. **Лучший итоговый вариант — Н4 + поток:** глубина (Depth Anything V2, приведённая к метрике по триангуляции между камерами) вместо сферы 6 м, затем глобальная подгонка швов. На реальных кадрах швы 1.65% → 0.80%, расхождение 26 → 18. Цена: GPU и ~22 с на панораму 2048.
3. **Н2 RAFT** — лучший вариант «только поток» и самый устойчивый к рассинхрону (B: 1.43%). Его стоит использовать как поток внутри варианта 2.
4. **Н1 глобальный сплайн** — лучший вариант без GPU: 9 с, швы −15…60%.
5. **Н3** даёт выигрыш только на реальных потолках у полюса, и небольшой. В UE хуже Н1.
6. **Н5** в текущем виде вреден: поворотом нельзя компенсировать смещение оператора за время задержки, а отсев пар с относительным поворотом больше 8° теряет данные. Правильное решение — аппаратная синхронизация.
7. Отдельный объектив на каждую камеру помогает в UE (синхронные кадры), но на реальных данных с рассинхроном переобучается: f получается от 598 до 721 px. Реальным камерам нужна разовая калибровка по ChArUco.
